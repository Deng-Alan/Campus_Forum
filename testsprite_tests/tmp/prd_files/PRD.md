# 校园论坛系统 产品需求文档（PRD）

## 1. 文档信息

| 项目名称 | 校园论坛系统 (Campus Forum) |
|---------|---------------------------|
| 版本号   | v1.0.0                    |
| 文档日期 | 2024-12-06                |
| 作者     | 产品团队                   |

## 2. 产品概述

### 2.1 产品定位
校园论坛是一个面向大学生群体的社交平台，提供学习互助、表白墙、匿名倾诉等功能，旨在为校园用户创建一个安全、友好、活跃的线上交流空间。

### 2.2 目标用户
- **主要用户**：在校大学生
- **次要用户**：校园管理人员、教师

### 2.3 核心价值
- 促进校园内学习交流与互助
- 提供情感表达的安全空间
- 构建积极向上的校园文化
- 保护用户隐私（支持匿名发帖）

## 3. 功能需求

### 3.1 用户系统

#### 3.1.1 用户注册
- **功能描述**：新用户通过邮箱注册账号
- **业务规则**：
  - 邮箱格式必须合法
  - 密码长度6-20位
  - 邮箱不可重复注册
  - 注册后自动创建用户资料

#### 3.1.2 用户登录
- **功能描述**：已注册用户通过邮箱密码登录
- **业务规则**：
  - 支持JWT Token认证
  - Token有效期7天
  - 支持Token自动刷新
  - 登录失败返回具体错误信息

#### 3.1.3 个人资料管理
- **功能描述**：用户可查看和编辑个人信息
- **包含字段**：
  - 昵称（必填，2-20字符）
  - 头像（支持上传，最大5MB）
  - 个人简介（选填，最多200字）
  - 学习状态（选填）
  - 学院信息（选填）

#### 3.1.4 用户偏好设置
- **功能描述**：用户可设置个人偏好
- **偏好项**：
  - 主题设置（深色/浅色）
  - 通知设置（开启/关闭）
  - 隐私设置

### 3.2 帖子系统

#### 3.2.1 发布帖子
- **功能描述**：用户发布不同类型的帖子
- **帖子类型**：
  - 学习互助（study_help）
  - 表白墙（confession）
  - 匿名倾诉（anonymous）
- **业务规则**：
  - 内容长度：1-5000字符
  - 支持上传一张配图（最大5MB）
  - 学习互助需选择科目标签
  - 表白墙需填写表白对象
  - 匿名帖子自动隐藏发布者信息
  - 每日发帖上限（系统可配置，默认3篇）
  - 新帖需要管理员审核

#### 3.2.2 帖子列表
- **功能描述**：分类展示帖子列表
- **展示维度**：
  - 按类型筛选（全部/学习互助/表白墙/匿名）
  - 按状态筛选（已审核/待审核）
  - 支持分页加载
  - 显示帖子基本信息（标题、内容预览、作者、时间、点赞数、评论数）

#### 3.2.3 帖子详情
- **功能描述**：查看单个帖子完整内容
- **包含信息**：
  - 完整内容
  - 配图（如有）
  - 作者信息（非匿名）
  - 发布时间
  - 点赞数、评论数
  - 评论列表

#### 3.2.4 帖子互动
- **点赞功能**：
  - 用户可对帖子点赞/取消点赞
  - 实时更新点赞数
  - 记录点赞用户
- **删除功能**：
  - 作者可删除自己的帖子
  - 管理员可删除任何帖子

### 3.3 评论系统

#### 3.3.1 发表评论
- **功能描述**：用户对帖子发表评论
- **业务规则**：
  - 评论长度：1-500字符
  - 支持对匿名帖子评论
  - 评论者信息公开显示

#### 3.3.2 评论互动
- **功能**：
  - 对评论点赞
  - 删除自己的评论
  - 查看评论列表

### 3.4 举报系统

#### 3.4.1 举报帖子
- **功能描述**：用户举报违规内容
- **举报理由**：
  - 垃圾广告
  - 违法违规
  - 恶意攻击
  - 淫秽色情
  - 其他原因（需填写说明）
- **业务规则**：
  - 举报需填写理由（10-200字）
  - 同一用户不可重复举报同一帖子
  - 举报后进入管理员审核队列

### 3.5 申诉系统

#### 3.5.1 提交申诉
- **功能描述**：帖子被删除/驳回后可申诉
- **业务规则**：
  - 申诉理由10-500字
  - 每个帖子只能申诉一次
  - 申诉后等待管理员处理

#### 3.5.2 申诉记录
- **功能**：查看我的申诉历史
- **显示信息**：
  - 申诉时间
  - 申诉理由
  - 处理状态（待处理/已通过/已驳回）
  - 管理员回复

### 3.6 建议反馈

#### 3.6.1 提交建议
- **功能描述**：用户向平台提交建议
- **业务规则**：
  - 建议内容10-1000字
  - 可选择建议类型
  - 支持查看处理状态

### 3.7 排行榜系统

#### 3.7.1 学霸排行榜
- **功能描述**：展示学习互助活跃用户
- **排序规则**：
  - 积分计算：发题+2分，答题+1分，获赞+0.5分
  - 时间维度：7天/30天/全部
  - 科目筛选：全部/数学/物理/化学等
- **展示信息**：
  - 排名
  - 用户昵称
  - 发帖数
  - 评论数
  - 获赞数
  - 总积分

### 3.8 管理后台

#### 3.8.1 管理员登录
- **功能**：独立的管理员登录入口
- **权限验证**：需要管理员角色

#### 3.8.2 数据统计
- **统计指标**：
  - 总帖子数（分类型统计）
  - 总用户数
  - 总评论数
  - 待处理举报数
  - 公告数量
- **图表展示**：
  - 每日发帖/评论趋势图（7天/30天）

#### 3.8.3 帖子管理
- **功能列表**：
  - 查看所有帖子
  - 设置精选帖子
  - 删除违规帖子
  - 批量操作

#### 3.8.4 审核管理
- **功能**：审核新发布的帖子
- **操作**：
  - 通过审核
  - 驳回（需填写理由）
  - 查看帖子详情（含配图）

#### 3.8.5 举报处理
- **功能**：处理用户举报
- **操作**：
  - 标记为已处理
  - 忽略举报
  - 删除被举报帖子

#### 3.8.6 申诉管理
- **功能**：处理用户申诉
- **操作**：
  - 通过申诉（恢复帖子）
  - 驳回申诉（需填写回复）

#### 3.8.7 建议管理
- **功能**：查看和回复用户建议
- **状态管理**：
  - 待处理
  - 处理中
  - 已完成
  - 已拒绝

#### 3.8.8 公告管理
- **功能**：发布和管理系统公告
- **公告属性**：
  - 标题（必填）
  - 内容（必填）
  - 类型（通知/活动/警告）
  - 是否置顶

#### 3.8.9 系统设置
- **可配置项**：
  - 每日发帖上限（默认3篇）
  - 其他系统参数

### 3.9 文件上传

#### 3.9.1 图片上传
- **应用场景**：
  - 用户头像
  - 帖子配图
- **限制条件**：
  - 支持格式：JPG、PNG、GIF、WEBP
  - 大小限制：5MB
  - 自动生成唯一文件名

## 4. 非功能需求

### 4.1 性能要求
- 页面加载时间 < 3秒
- API响应时间 < 500ms
- 支持1000并发用户
- 列表接口支持分页，每页20条

### 4.2 安全要求
- 所有API需要JWT认证（除登录、注册、公开内容）
- 密码使用BCrypt加密存储
- 防止SQL注入、XSS攻击
- 敏感操作需二次确认
- 文件上传需类型和大小校验

### 4.3 可用性要求
- 系统可用性 > 99%
- 支持移动端自适应
- 关键操作有loading状态提示
- 错误信息友好明确
- 支持深色/浅色主题切换

### 4.4 兼容性要求
- 浏览器：Chrome、Firefox、Safari、Edge最新版本
- 移动端：iOS 12+、Android 8+
- 屏幕分辨率：最小支持375px宽度

### 4.5 数据要求
- 使用PostgreSQL数据库
- 使用Redis缓存热点数据
- 定期备份用户数据
- 日志保留30天

## 5. 技术架构

### 5.1 前端技术栈
- 框架：Next.js 14 (App Router)
- 语言：TypeScript
- 样式：TailwindCSS
- 状态管理：React Hooks
- HTTP客户端：自定义封装（基于Fetch API）
- 组件库：自定义组件

### 5.2 后端技术栈
- 框架：Spring Boot 2.7.x
- 语言：Java 11
- 数据库：PostgreSQL
- 缓存：Redis
- ORM：MyBatis Plus
- 认证：JWT
- 构建工具：Maven

### 5.3 部署架构
- 前端：Vercel/Netlify
- 后端：云服务器
- 数据库：云数据库
- 文件存储：本地存储/OSS

## 6. 接口清单

### 6.1 认证相关
- POST /api/v1/auth/register - 用户注册
- POST /api/v1/auth/login - 用户登录  
- POST /api/v1/auth/refresh - 刷新Token
- POST /api/v1/auth/logout - 退出登录

### 6.2 用户相关
- GET /api/v1/users/me - 获取当前用户信息
- PUT /api/v1/users/profile - 更新用户资料
- GET /api/v1/users/{id}/profile - 获取指定用户信息

### 6.5 反馈相关

- GET /api/v1/appeals/my - 获取我的申诉

### 6.6 排行榜

## 9. 风险与对策

### 9.1 技术风险
- **风险**：高并发下系统性能问题
- **对策**：使用Redis缓存、数据库优化、负载均衡

### 9.2 安全风险
- **风险**：用户数据泄露、恶意攻击
- **对策**：加密存储、权限验证、限流防护

### 9.3 运营风险
- **风险**：违规内容传播
- **对策**：内容审核机制、举报系统、管理员干预

### 9.4 用户体验风险
- **风险**：功能复杂度影响使用
- **对策**：简化交互流程、新手引导、用户反馈收集

## 10. 总结

校园论坛系统旨在为大学生提供一个综合性的线上交流平台，通过学习互助、情感表达、匿名倾诉等核心功能，满足校园用户的多样化需求。系统采用现代化的技术架构，注重用户体验和数据安全，通过完善的管理机制确保社区的健康发展。
